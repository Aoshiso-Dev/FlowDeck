# FlowDeck Dial firmware

GUITION **JC3636K518C_I_YR1** 用の USB シリアル接続ファームウェアです。リングを回して選択対象の値を調整し、画面中央の短いタップで次の対象へ切り替えます。物理的な押下入力はメーカー回路図で確認できないため、GPIO0 を押しボタンとして使用しません。

270 度の太いアークと中央の大きな数値で値を表示します。通常は対象名、%、RPM、3 温度、動くアイコンとページ位置だけを表示します。対応 PC との接続では、回転直後の予定値を破線のアークで示し、最新の冷却設定が全台で確認されたときだけチェックと台数を約 1 秒表示します。異常時は「適用失敗」「確認不可」「操作不可」「未接続」などの短い通知に置き換え、詳細は PC 側で確認します。照明設定の保存は物理出力の検証とは区別して「出力未確認」と表示します。旧 PC との接続では確認値を表示し、成功チェックは表示しません。未知の対象の長い名前は 4 秒ごとのページ切替で読めます。日本語は U8g2 の GNU Unifont Japanese3 に含まれる 3,905 字を使用します。絵文字やこの範囲外の字形は保証しません。

## 対応基板

メーカー [GUITION K5-series](https://github.com/guitionofficial/K5-series) のピン定義、V1/V2 回路図、Arduino サンプルを基準とします。

| 機能 | 設定 |
| --- | --- |
| MCU / メモリ | ESP32-S3、16 MB flash、8 MB OPI PSRAM |
| 方向スイッチ A / B | GPIO8（右）/ GPIO7（左）、独立 active-low 接点 |
| LCD | ST77916、360 × 360、QSPI |
| LCD CS / SCK / D0–D3 | GPIO14 / GPIO13 / GPIO15–18 |
| LCD RST / BL | GPIO21 / GPIO47 |
| タッチ | CST816、I²C アドレス 0x15、400 kHz |
| タッチ SDA / SCL / INT / RST | GPIO11 / GPIO12 / GPIO9 / GPIO10 |
| USB | ESP32-S3 hardware USB Serial/JTAG、CDC on boot |

GPIO0、I²S、電源回路、第 2 ESP32 は制御しません。回路資料の照合とビルドは、接続された個体での表示、向き、1 ノッチあたりの回転量、タッチ、PSRAM 動作の確認を代替しません。実機受け入れで必要な方向調整は `src/board_config.h` の `EncoderDirection` で行います。

LCD は GUITION の `ST77916_LVGL_DEMO/scr_st77916.h` にある基板専用の初期化を `src/guition_st77916.h` で使用します。コマンド・データ・待機時間はメーカー配列と同一で、RGB565 の COLMOD 設定を別途送ります。回転 0、物理 INVON（0x21）、QSPI 40 MHz です。出典 Git blob は `388c074c73a915b3aba1f46a7a9837850b65ac48`、元ファイル SHA-256 は `6a6de265eeeddb764af7394d90d72a150175bed7fd45668c900748fc3c449ade` です。

0.1.1 では、実機で表示が乱れた 0.1.0 の汎用 ST77916 初期化をこの基板専用設定へ修正しました。QSPI ではガンマ等の複数バイト設定を `WRITE_C8_BYTES` で同じコマンドとして送り、画素 RAM 転送と区別します。

0.1.2 は接続問題を調べる診断版です。`hello.diagnostics` に USB false 遷移数、状態失効数、最大 loop 間隔・描画時間、状態受理数・拒否フレーム数・identify 数・受信バイト数・最終状態受理からの経過時間を付加します。LCD 初期化、通信・失効・操作の動作は 0.1.1 のままです。

0.1.3 は、実機の診断で確認した HWCDC の一時的な false 状態によるセッション消失を修正します。USB 状態が false の間は物理入力を破棄して送信を抑止しますが、受信を継続し、セッションの有効性は従来の 3 秒間の状態更新で判定します。状態失効時には部分受信フレームと入力を破棄し、新しい `welcome` を必要とします。診断カウンターは維持します。

0.1.4 は回転を検知しなかった方式の不一致を修正します。メーカー回路図の SW2（SSCM110100）と `ST77916_LVGL_DEMO/bidi_switch_knob.c` が示す通り、この基板の A/B は quadrature 位相ではなく左右の独立接点です。公式コードと同じ 3 ms 周期・2 回の low サンプル後の復帰で 1 回を数えます。描画中も動く独立 `esp_timer` を使用し、同時／重複接点とリセット時に押されたままの接点は完全に離すまで無視します。診断には GPIO エッジ数、2bit ピン状態別のエッジ数、左右の復号数、破棄ステップ数とタイマー初期化状態を追加します。

0.1.5 は表示だけを太いアーク案へ更新します。中心 (180, 180)、外半径 164 px、内半径 146 px のアークを画面座標の 135 度から時計回りに 270 度描きます。0–100% の確認値を示し、中央の数字と小さい `%`、上部の対象名 2 行、下部の状態・対象番号・中央タップ案内を配置します。設定下限／上限は目印と文字で示し、確認値が設定範囲外でも数値・アークを丸めません。処理中は確認値を維持し、接続待ち／対象なしは `--` にします。名前は幅 208 px、メッセージは幅 192 px の 2 行ずつで全文をページ表示し、新しい文は最初のページから始めます。値だけの更新ではページ進行を止めません。80 ms の描画間隔制限を維持し、常時アニメーションは行いません。入力、通信、LCD 初期化は 0.1.4 と同じです。

0.1.6 は `responsiveInput:1` を双方で選択した場合に、予定値の即時表示と絶対値 `set` を使用します。同時に送る操作は 1 件で、その適用中の回転を最新の予定値へまとめます。同じ操作の成功を明示する応答だけが次の送信を許可します。失敗・未検証・外部変更・対象変更・切断では残りの予定値を破棄します。描画間隔を 40 ms とし、折返し計算を文字列ごとにキャッシュします。PSRAM に前フレーム約 253 KiB を保存し、変わった 16 行帯だけを QSPI 転送します。確保できなければ全画面転送へ戻ります。画面解像度、初期化、40 MHz クロックは変更しません。診断に描画／転送の最大時間、直近の転送画素数、描画回数、差分転送の有効状態を追加します。これらの設定値は実機で測る応答時間とは区別します。

0.1.7 は PC がまとめる「全ファン・N台」「ポンプ・N台」の操作対象と、各台の確認値が混在する状態に対応します。台数と対象の選定は PC が行います。混在時の中央表示は「混在」、小行は「固定出力 基準 xx%」で、基準は PC が返す各台確認値の最大値です。アークは共通値として塗りつぶさず、基準位置の目印だけを示します。回転後は共通予定値を大きく即表示し、確認値が混在していることも残します。全台の確認が完了したときだけ共通確認値へ切り替えます。部分失敗の「確認 2/3」等は PC メッセージとして全文表示し、残りの予定値を取り消します。単一ポンプや均一な群の表示は従来通りです。

0.1.8 は大きな % 表示の下に回転数を追加します。PC が全台分の新しい RPM を取得した場合だけ「1200-1500 RPM」の範囲、または同じ値／単一台の「1200 RPM」を示します。0 RPM も有効です。一部または全台が未取得の場合は「-- RPM (2/3)」「-- RPM (0/3)」のように取得数を示し、一部だけの範囲を全台の値として表示しません。通信の状態が失効したら過去の RPM を消します。RPM は観測値であり、予定値の適用確認や次の操作の根拠にはしません。RPM だけの更新では予定値・送信中の操作・長文のページ進行を維持します。旧 PC が RPM フィールドを送らなければ従来の配置で表示します。太いアーク、% の即時プレビュー、確認値／混在表示、2 行のメッセージ全文ページングは維持します。

0.1.9 は RPM の下に CPU・GPU・水温の 3 列を常時表示します。CPU と GPU は四捨五入した整数 °C、水温は小数 1 桁の °C です。センサーの選択・鮮度判定は PC が行い、水温にはユーザーが指定した T_SENSOR1 を使います。温度は選択対象と独立した PC 全体の観測値で、全ファンとポンプを切り替えても同じ位置で読み取れます。対象がなくても新しい状態を受信していれば表示し、通信失効時には消します。個別の未取得値は「--°C」で、0°C とは区別します。温度だけの更新・欠損では予定値、適用中の操作、適用確認、メッセージのページ進行を変更しません。新しい配置では中央の数字を 8 倍（56 px）にして、太いアーク、RPM、確認値、設定範囲、2 行メッセージ、状態、中央タップ案内を残します。温度 3 フィールドをすべて省略する旧 PC には 0.1.8 と同じ配置を使います。

0.1.10 は全ファンをライム（#A3D936）と静止した 4 枚羽根、ポンプを青（#4DB8FF）と水滴で区別します。上部には対象名と実際の台数を表示します。色は対象を示し、調整中・適用中・操作不可でも変わりません。大きな % は白で即時追従し、確認済みの値・適用状況・操作不可の理由を従来の位置に残します。ファンのアイコンは RPM を表すアニメーションではありません。識別には新しい冷却状態の厳密な `targetId`（`cooling:all-fans` / `cooling:pumps`）を使い、名前や RPM から推測しません。未知の対象・照明・対象なし・通信失効では中立色を使います。未知の対象名は従来どおり全文をページ表示し、通信失効では接続待ちを表示します。RPM・3 温度・混在値・設定範囲・適用確認・メッセージ全文・入力処理・プロトコルは維持します。

0.1.11 は新しい実測 RPM が全台分揃っているとき、ライムの 4 枚羽根を回転させ、青い水滴の内側に明るい光を上向きに流します。水滴の外形・ファンの外枠・対象の色は固定します。全ファンでは最小と最大 RPM の中間値を演出用に使います（各台の平均ではありません）。ファンの見かけの速さは約 0.3–1.2 回転/秒、ポンプの光は約 1.25–4 秒/周期に縮め、実回転や流量の測定表示とは区別します。0 RPM、RPM の未取得・一部取得、対象不明、照明、通信失効では動かしません。`-- RPM` と取得台数の表示は維持します。動きは設定 %、予定値、適用確認、操作可否から決めず、操作不可でも有効な実測 RPM があれば表示します。

アニメーションだけのフレームではアイコン周囲の 39 × 39 px（1,521 画素）だけを消去・描画・QSPI 転送し、値・温度・メッセージ・アークは描き直しません。前フレーム保存領域の同じ部分も更新し、通常表示の差分帯転送との整合を保ちます。通常更新と共通の最短 40 ms 間隔で動かし、動作中の待機や入力送信の追加は行いません。位相は範囲を限定した整数で計算し、時刻の周回に対応します。対象・台数・セッションの変更で位相を初期化し、250 ms を超える処理停止分を早送りしません。診断にアニメーション専用フレーム数、描画・転送・合計の最大時間、直近の転送画素数を追加します。RPM・3 温度・即時プレビュー・混在・適用確認・設定範囲・全文ページ表示と入力／制御の処理は維持します。

0.1.12 は通常時の説明文、状態文、操作案内、設定範囲の文章を取り除き、確認中はアーク全体を破線にして小さな 3 点を表示します。対象名・台数、%、RPM、CPU/GPU/水温、色とアイコン、即時プレビュー、設定下限／上限の目印は維持します。混在は共通値として塗らず「混在」を表示し、RPM と温度の欠損も従来どおり区別します。全ファン／ポンプの位置は下部の 2 点で示します。

チェックは表示専用の監視処理で制御します。送信中の最新 `set` と同じ `ackSeq`、同じ操作文脈、`confirmed`、全台が均一、要求値との一致、次の予定値がないことを確認した場合だけ 1,000 ms 表示します。古い ACK、定期的な状態受信、タップ、照明の `saved`、RPM・温度の更新ではチェックを開始・延長しません。次の回転、対象／文脈／セッション／観測値の変更、操作不可、失効でも消します。`rejected` は「適用失敗」、`unverified` は「確認不可」と中央の `--` を表示し、出力アークを塗りません。未接続・対象なし・操作不可・タッチ異常も短く表示します。適用失敗はタイマーで消さず、状態が解消するまで保持します。プロトコル、入力のサンプリング、送信と適用確認の制御処理は変更しません。

表示は LCD コントローラーの回転値 `2` で 180 度反転します。Canvas の論理座標を維持し、全画面・差分帯・39 × 39 px のアイコン更新を同じ回転設定で転送します。中央タップの判定領域は中心対称なので変更せず、リングの右／左方向も変更しません。

0.1.13 は中央の % の大きさを維持し、RPM と CPU/GPU/水温の数字を従来の 2 倍フォントから 3 倍フォント（約 1.5 倍）へ拡大します。RPM を中央数字の下、温度のラベルをその下、3 列の温度数字をさらに下へ配置し、短い通知と約 1 秒のチェック表示を下部へ移します。温度の単位は小さなラベル行へ分離し、度記号は字形の有無に依存しない円として描きます。CPU/GPU は整数、水温は小数 1 桁を保ち、上限の `150.0` も同じ大きな数字で表示します。

RPM は文字列の実際の幅を測り、長い数値範囲や取得台数がある場合だけ、画面内へ収まるサイズに調整します。値や単位、範囲の片端を省略しません。0・未取得・混在は区別し、3 温度を送らない旧 PC の配置は変更しません。中央 %、対象アイコンと動き、即時反応、確認中の破線、最新成功の短いチェック、180 度反転、起動時に隙間を計算する破線描画の最適化、および入力／適用確認の制御処理を維持します。

## ビルドと検証

リポジトリ直下から、ポートを開かないビルドを実行します。

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build-dial-firmware.ps1
```

このスクリプトは日本語を含むパスに対する GCC の制限を避けるため、一時的なドライブ割り当てを使用します。生成物は `.pio/build/jc3636k518/` にあり、ソース公開対象に含めません。

portable core は実装と同じ `src/dial_core.h` をホスト側でコンパイルして検証します。

```powershell
python scripts/test-dial-firmware-host.py
```

実際の描画関数・Arduino_GFX・日本語フォントを使う画面検証は次のコマンドです。ハードウェア部分だけをフレームバッファに置き換え、画像と結果を `artifacts/dial-development/display-host/` に保存します。全ファン／ポンプの 0・60・100%、混在、予定値、適用中、操作不可、失効、旧配置、長文、未知の対象を検証し、文字の重なり・円形パネル外への描画、差分転送後の全画面一致も確認します。実機の色や表示品質の最終確認は別途必要です。

```powershell
python firmware/dial/test/render_host.py
```

テスト対象は LF 込み 4096 バイトの境界、オーバーフロー後の再同期、UTF-8 と型・範囲検証、セッション不一致、3 秒失効、時刻の周回、シーケンスの継続、独立方向パルスと短いチャタリング・長時間保持・接点の重複・保持中のリセット、中央タップ・長押し・スワイプ・読み取り失敗です。さらに応答の対応付け、成功後の集約送信、古い応答の拒否、失敗・未検証・文脈変更時の取消、応答喪失、長い適用中の継続、旧 PC 互換、差分帯転送による画面の完全再構成を検証します。群では混在時の最大値基準、100% への同値 set、全台確認後の継続、部分失敗、台数・対象変更、追加フィールドの省略と境界を検証します。RPM は省略／null／0／上限／部分取得の型・範囲・台数整合と、適用待ち中の更新や未取得によって予定値を取り消さないことを検証します。ビルド／ホストテストは COM ポート接続、リセット、flash 書き込みを行いません。

温度は 3 項目それぞれの省略／null／0／上限、負値・小数・型違い・範囲外の拒否、未取得への置換、対象なしと旧 PC 互換、切断／失効時の消去、プレビュー／送信中／集約中／確認済みの各段階で温度だけの更新が操作を変更しないことを検証します。

## プロトコル v1

UTF-8 JSONL、LF 区切り、**LF 込み最大 4096 バイト**です。過大フレームは次の LF まで破棄します。追加 JSON やごみを付けたフレームも拒否します。

1. PC の `identify` に `hello` を返します。未接続時は 1 秒周期でも `hello` を送ります。
2. PC の `welcome` が `sessionId` を設定します。`hello` の `responsiveInput:1` に対して `welcome` も同じ値を返した場合だけ、応答を明示する連続調整を有効にします。
3. PC の `state` が対象と確認値を設定します。PC は 1 秒以内の周期で更新します。
4. ダイヤルの `input` は直近の `sessionId`、`stateId`、`targetId` をそのまま返します。

```json
{"v":1,"type":"hello","deviceType":"FlowDeckDial","deviceId":"dial-001122334455","bootId":"0123456789abcdef0123456789abcdef","firmwareVersion":"0.1.13","responsiveInput":1}
{"v":1,"type":"welcome","sessionId":"s1","responsiveInput":1}
{"v":1,"type":"state","sessionId":"s1","stateId":"r1","targetId":"fan1","label":"CPU ファン","kind":"cooling","value":45,"min":20,"max":100,"step":1,"index":1,"count":2,"enabled":true,"busy":false,"message":"確認済み","operationId":"o1","ackSeq":0,"ackStatus":"none"}
{"v":1,"type":"input","sessionId":"s1","stateId":"r1","targetId":"fan1","seq":1,"action":"set","value":46}
```

- `sessionId`、`stateId`、`operationId` は最大 64 バイト、`targetId` と `label` は最大 192 バイト、`message` は最大 256 バイトの UTF-8 です。
- `value` は 0–100 の確認値です。`min` / `max` は次に設定可能な範囲であり、停止中のファン等では確認値がこの範囲外でも受け入れます。`step` は 1–100、`index` は 1 始まり、`count` は 1–10000 です。
- `valueMixed`（bool、既定 false）と `memberCount`（整数、対象あり 1–64、対象なし 0）は省略可能です。省略時は単一対象として従来と同じ表示になります。`valueMixed=true` は 2 台以上に限り、`value` は各台確認値の最大値です。この基準値を共通確認値とは表示しません。`count` は選択できる群の数、`memberCount` は選択した群に含まれる機器・端子数です。
- `rpmMin` / `rpmMax`（整数または null）と `rpmCount`（整数）は省略可能です。3 項目すべての省略は旧 PC として RPM 行を表示しません。いずれかがある場合は `rpmCount` が必須で、0–`memberCount` の範囲です。0 の場合、最小／最大は null または省略に限ります。1 以上なら最小／最大とも 0–1,000,000 の整数かつ最小 ≤ 最大で、1 台なら両値が同じ必要があります。全台分の新しい値が揃うまで画面の数値範囲を表示しません。RPM は操作の文脈比較に含めず、値だけの更新で入力権限を変更しません。PC 側で実際の安全条件や利用可否が変わる場合の取消は従来通りです。
- `cpuTempDeciC` / `gpuTempDeciC` / `waterTempDeciC` は省略可能な整数または null で、単位は 0.1°C、有効範囲は 0–1500 です。3 項目すべての省略は旧配置を選択し、いずれかが存在すると 3 温度の配置を選択します。各項目の null または省略は未取得で、前の値を引き継ぎません。PC は既存の温度鮮度・妥当性検証を保ち、変換前の実測値が 0°C より大きく 150°C 未満の場合だけ整数へ丸めます。丸め結果の端点 0 / 1500 は有効です。CPU・GPU は表示時にさらに整数 °C へ四捨五入し、水温は小数 1 桁を表示します。温度は群に依存しない観測値で、操作の文脈・適用確認には含めません。`count=0` の新しい状態でも温度は表示できます。通信の状態失効では過去の値を消します。
- 対象がないときは `targetId=""`、`index=0`、`count=0`、`enabled=false` です。
- `enabled` は新しい調整を開始できるかを示します。応答待ちの自身の操作では同じ `operationId` が続く間だけ回転を保持します。対象が存在して `busy=false` なら `enabled=false` でも中央タップを送れます。ただし連続調整の予定値／送信中の操作がある間はタップを送らず、タップを後から再生しません。登録済みかどうかの最終判定は PC が行います。
- `rotate` の `delta` は −20–20（0 を除く）、`press` は 0 です。`seq` は起動中単調増加する uint32 で、再接続時にもリセットしません。上限到達時は再起動まで送信を停止します。
- `set` の `value` は `min`–`max` の整数です。FW が保持するのは最新の予定値 1 個で、送信済み要求の再送や複数操作の待ち行列は作りません。
- 混在状態では基準値と同じ `set` にも意味があります。例えば最大確認値 100% の群を右へ回した場合、1 回の `set:100` を送り、他の台も 100% へ揃えます。全台が同じ値で確認された後は、この同値送信を抑止します。
- `ackSeq=0,ackStatus="none"` が初期状態です。`pending` は処理中、`confirmed` は確認済み、照明専用の `saved` は保存確認済みで物理出力確認とは異なります。`unverified` と `rejected` は継続を許可しません。送信した `seq` と同じ `confirmed`／照明 `saved` だけが、同じ `operationId` の最新予定値を次に送ることを許可します。普通の heartbeat、古い応答は送信中の操作を解除しません。
- PC は自身の適用による busy／確認値更新では `operationId` を維持し、外部世代・編集・対象・設定範囲・利用可否の変更では更新します。FW も対象／種類／範囲／step／memberCount の変化を独立に検査し、残りの予定値を取り消します。自身の適用によって混在が解消されることは継続を妨げません。対応する完了応答でも `valueMixed=true` が残る場合は継続しません。
- 接続断、セッション変更、文脈変更、失敗、未検証、3 秒以上状態が更新されない場合は古い入力を破棄します。送信中の `seq` に一致する応答も 3 秒以上届かなければセッションを失効させます。`pending` の定期応答が続く長時間操作は維持します。失効後は新しい `welcome` が必要です。USB 状態の一時的な false では、すでに送った操作の結果待ちを維持し、追加の予定値だけを破棄します。
- 回転は右／左の独立接点を 3 ms 周期で読み、2 回連続 low から high へ戻ったときに 1 ステップとし、送信間隔は最低 40 ms です。旧 PC（`welcome` に `responsiveInput:1` がない接続）では従来の相対 `rotate` を使い、次の `state` まで追加回転を破棄する動作を維持します。
- 中央半径 108 px 内、35–550 ms、移動距離 18 px 以下の単指タップを、離した時点で 1 回だけ送ります。長押し、スワイプ、複数指、読み取り失敗、接続前からの接触は取り消します。
